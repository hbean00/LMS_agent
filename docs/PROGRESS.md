# 작업 기록

에이전트가 다음 턴에 읽으려고 남기는 기록. 낡으면 고친다. 마지막 갱신: 2026-11-12 17시.

## 문제 정의

Canvas(고려대 mylms.korea.ac.kr 등) 과제 중 **이메일·종이로 내는 과제는 Canvas에 마감이 없다.** 마감은 공지·메시지·강의계획서·과제 설명에만 글로 적혀 있다.
v0.1: 그 글에서 마감을 과제 단위로 찾아 근거와 함께 승인받고 .ics로 내보냄.
v0.2(진행 중): **개강부터 종강까지의 학기 관리자.** 보는 단위가 주(week)와 과목. PC 화면 + 휴대폰은 캘린더로(선택 a+b). 디자인은 사용자의 PPT 스타일(흰 배경·버건디 #900A31·Pretendard·네 모서리).
목표: 누구나 내려받아 자기 Canvas에 연결해 쓰는 배포 가능한 앱. 공개 저장소 https://github.com/hbean00/LMS_agent

## 사용자가 정한 것

- 휴대폰 화면은 만들지 않는다(PC 우선). 휴대폰은 캘린더로 본다.
- 업데이트는 **켤 때마다 자동** + 버튼. 주 1회 전체 확인은 하지 않는다(해시 비교로 매번 바뀐 곳만 읽으므로 필요 없음).
- 완료 기준: 매번 다 읽지 않고, **탐색 목표(바뀐 곳)만 잡아** 실행한다. 등록됐다는 근거를 표시한다.
- 학점: A+ A0 B+ B0 C+ C0 D+ D0 F. 기본 분포 누적 15/30/45/60/75%, D+/D0은 0%(C0 20%, F 5%로 둠 — 사용자 확인 필요).
- 구글 캘린더는 **API로 자동 반영**(수동 .ics 가져오기 대신). .ics는 대안으로 남김.

## 구조

- 흐름과 계약: `CLAUDE.md`, `docs/CONTRACTS.md`(1~3장 v0.1, 4장 학기, 5장 증분·근거 사슬).
- 증분 수집(M1, 완료): `core.collect(prev=…)`는 메시지 본문을 `last_message_at`이 바뀐 대화만 받고, `core.build_items(extracted=…)`는 글 내용 해시가 같으면 지난 결과를 재사용. 처음 실행·`RULES_VERSION` 변경·전체 다시 확인일 때만 전부 읽음. 실행 기록 `store.data["runs"]`.
- 근거 사슬(M2 API 완료): item `first_seen → decided_at → exported_at(+export_stale)`.
