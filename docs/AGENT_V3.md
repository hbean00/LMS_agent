# 에이전트 v3 설계 — 말로 시키면 해석해서 직접 한다 (v0.9.0 예정, 2026-11-15)

## 사용자 요청과 결정

- "에이전틱 UI를 통해 데이터 수정·설정 변경이 가능하기를 — 학점 비율도. 이것만이 아니라 AI CLI가 어떤 명령에 해당하는지 해석하고 변경하는 하네스".
- (보충) "MCP의 원리를 꼭 따를 필요는 없지만, '구글 캘린더 일정 반영해줘' 하면 반영해 주는 것처럼 AI가 어떤 동작을 의도하는지 해석하고 직접 행동을 수행할 수 있어야 한다.
  '모든' 동작이라 한 점은 사과 — **AI 끄기는 자기 행동을 끄게 하는 것이라 거절**이 맞다. **AI 허용 횟수, 개인정보 변경도 마찬가지**."
- 계기: "ASIC 학점 잘 주신대 비율 조정도 해줘" → v0.8.x는 학점 비율 바꾸기에 강의 글의 근거 인용을 요구해서 거절했다.

## 지금(v0.8.1)

화면이 하는 변경 48가지(POST 경로) 중 에이전트가 할 수 있는 것은 동작 23가지(actions 카탈로그)와 근거가 필요한 데이터 변경 10가지뿐.
성적 설정(비중·점수·학점 비율·수강 인원)·항목 제목/마감 직접 고치기·직접 입력 글·자료 설정·구글 캘린더 고르기 등은 말로 못 한다.

## 설계

1. **능력 목록은 코드에서**: 화면의 API 경로마다 옆에 설명(무엇을 하는지·받는 값의 모양·위험 등급·바뀌기 전후를 말하는 법)을 붙인다.
   설명이 없는 POST 경로가 있으면 테스트가 실패 → 기능이 늘어도 에이전트가 자동으로 따라간다.
2. **사용자의 지시가 권한**: 사용자가 직접 시킨 변경은 `decided_by: "user"`(이유 = 사용자의 말), 강의 글 근거가 필요 없다. AI가 스스로 찾은 것만 지금처럼 근거 인용.
   애매한 지시("학점 잘 주신대")는 거절하지 않고 구체적인 값으로 제안 카드("A 30→40% · B 40→40% — 지금 → 바꾼 뒤").
3. **화면 단추와 같은 길**: 그 API를 앱 안에서 그대로 부른다(지금 actions처럼) — 검증도 화면과 같다.
4. **되돌리기는 공통으로**: 실행 전후 상태를 기록하고 [되돌리기]는 그 사이 바뀌지 않았으면 이전 상태로. 기능마다 되돌리기 코드를 따로 쓰지 않는다.
5. **등급**
   - 바로 하고 [되돌리기]: 이 PC 안의 변경 — 설정, 성적·학점 비율·점수, 마감 추가/고치기/빼기, 과목 종류, 연결, 공부 계획, 체크리스트, 알림.
   - 바로 하기(분명히 시켰을 때): 구글 캘린더에 반영(일정은 앱 상태에서 다시 만들어지므로 되돌리면 다시 맞춰짐), 동기화, 자료 받기.
   - 확인 카드: 되돌리기 어려운 것 — 업데이트 설치, 앱 끄기, 컴퓨터 켤 때 자동 실행(OS 등록), 구글 연결 해제.
   - **거절(사용자 결정)**: AI 켜기·끄기·실행기 바꾸기(자기 행동을 끄거나 바꿈), 하루 AI 사용 한도, 개인정보 — 학번, Canvas 토큰·로그인·로그아웃, 구글 동의, 데이터 지우기.
     거절할 때는 그 설정 칸을 열어 주고 "직접 바꿔 주세요"라고 말한다.
6. **AI에게**: 영역별 개요(`list_capabilities(area)`) → 필요한 것의 자세한 모양만 → `act(capability, params)`. 이름(과목·항목·평가 항목)은 하네스가 id로 바꾼다.
7. **확인 방법**: 실제 AI로 명령 30개 평가 세트(해석 정확도·잘못 바꾼 수·거절해야 할 것을 거절했는지).
